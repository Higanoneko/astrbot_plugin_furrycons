# FurryCons 展会图片插件

面向 AstrBot 的 FurryCons 展会图片查询插件。已提供详情、默认/日期/省市查询、名称搜索、稳定分页、持久查询短码、缓存、全部结果单图、可配置裸交互、原文件入口、两套内置主题、本地 ZIP 导入更新、会话主题、独立改色、可选 AI 总结及 WebUI 管理。NapCat / OneBot 实际收发已获维护者确认，QQ 官方与 Telegram 实际收发验收按维护者安排暂缓。0.2.4 提供官方海报和主办方 Logo、三种可切换图文排版及升级的 Liquid Glass；列表和详情均在同一信息卡片内左侧显示文字、海报按卡片高度等比显示，宽度自然延伸，左侧空白由海报边缘取色补齐并平滑模糊过渡。Discord 计划在 P2 完成，主题商店计划在 P3 落地。

## 当前安装与使用

将本目录作为 AstrBot 插件安装，保留 `furrycons/`、`themes/`、`assets/` 和配置文件。最低支持 AstrBot 4.29.1，已验证该版本和 Python 3.14.7；项目代码要求 Python 3.12 及以上。

通过 AstrBot 插件页安装时，由 AstrBot 按 `requirements.txt` 安装 Python 依赖。若安装或加载失败，请附 AstrBot/Python 版本和脱敏错误日志[提交 issue](https://github.com/Higanoneko/astrbot_plugin_furrycons/issues)。

安装后先在快速配置页检测浏览器；已有兼容浏览器且自检通过时即可使用。缺少浏览器时可点击“安装匹配 Chromium”，或在 AstrBot 使用的 Python 环境运行 `python -m playwright install chromium`。Linux 缺少系统依赖时按诊断指引运行 `python -m playwright install-deps chromium`，权限不足时由宿主管理员处理。也可在插件配置填写现有兼容 Chromium 的完整路径。

在 AstrBot 插件配置中填写 FurryCons 工作台提供的 API Key，Authorization 使用原值。数据源默认 `https://api.furrycons.cn/open`，显示时区默认 `Asia/Shanghai`。保存后重载插件。

首次使用可在聊天中发送 `/FEC 查询`，再发送 `/FEC 选择 1` 查看第一场详情；结果较多时发送 `/FEC 下一页`。这些明确命令使用本人在当前聊天最近一次成功生成的列表，无需开启裸触发。想按名称查找时使用 `/FEC 搜索 <名称>`。操作他人或较早的列表时，引用该图，或使用图上的短码：`/FEC 选择 <短码> <序号>`。下文列出筛选、主题和其他进阶用法。

发送 `/FEC 帮助` 或只发送 `/FEC`，可在聊天中查看这些步骤及筛选、排版、主题的示例。入口更改后请使用新的入口名称。

0.2.5 改善首次使用与日常管理：快速配置页提供三步入门、分区导航和常驻保存操作，低频选项按需展开。切换主题或刷新时会保留当前页面内的配色草稿；预览明确使用已保存的配色，保存后自动更新已有预览并保持排版。关闭或重开页面前请先保存草稿；普通配置保存后仍需重载插件。

0.2.13 进一步改善查询和故障恢复：选择与翻页可省略短码，列表附文给出可直接发送的操作；失败的新查询不会替代最近成功列表。普通配置显示未保存状态，重新读取时保留草稿，另有明确的“放弃草稿并重新读取”操作；草稿仅在当前页面内保留。首次读取失败可就地重试，安装状态短暂断连会自动重试，也可手动刷新。主题变更已保存但目录刷新失败时会分别说明，并提供只重试读取的入口。可选缓存故障会继续尝试实时查询，引用记录失败也不会重复发送已经提交成功的图片。

也可从插件卡片的详情打开“FurryCons 快速配置”可视化视图，在 Dashboard 内配置数据源、时区、分页与缓存、入口及功能别名、裸触发和总结开关。页面通过框架 bridge 调用受认证保护的插件 API，不读取父页面登录信息。API Key 只显示是否已配置；留空保存会保留原值，勾选清除才删除。无效值或入口冲突不会保存，陈旧页面需重新读取配置。保存结果会标明待重载状态；回到插件管理页重载，再重新读取即可确认当前生效入口。

配置沿用 AstrBot 的 `data/config/astrbot_plugin_furrycons_config.json`，由框架原子写入，与原生插件配置共用一份数据；插件目录更新不会覆盖它。Dashboard 登录身份或有框架 `plugin` 管理权限的 API 凭据可管理此接口，聊天管理操作独立检查机器人管理员身份。

快速配置页提供浏览器检测、中文自检图下载和主动安装。下载源 `browser_download_host` 可留空使用 Playwright 官方源；代理 `browser_download_proxy` 与连接超时只用于安装，先保存再点击“安装匹配 Chromium”。任务后台执行，日志与状态保存在插件数据目录，重开页面可查看；插件重载会中断正在进行的安装，之后需重新检测并主动发起。只有实际中文图片渲染通过才显示可用。已有浏览器路径需保存并重载后检测，下载匹配运行时不会自动覆盖自定义路径。Linux 缺少共享库或安装权限时按页面指引由宿主管理员处理，下载镜像不能替代系统依赖源。

同页“主题管理”可浏览已安装主题、用真实模板预览示例列表和详情、导入/更新/导出 ZIP、另存布局副本、设置主色及明暗和声明的高级颜色，以及全局或指定会话默认值。这些主题操作立即用于后续查询，无需重载；预览资料明确标为示例。更新仅针对明确选择的本地主题且 ZIP 标识必须一致；先校验后替换，保留独立配色、默认值和插件数据目录中的 `.previous-` 旧包备份。商店、在线安装与在线更新仍属 P3。

默认查询从今天起 365 个自然日，每页 8 场；日期待定记录单独标注，不沿用延期旧日期。名称搜索不限日期，单匹配仍返回候选供选择。查询交互默认有效 24 小时并持久化；同聊天其他用户可用短码，不能跨聊天操作。裸数字、名称和 UUID 触发默认关闭，须由机器人管理者配置；数字开启后仅对应本人在此聊天的最近查询。

新查询和名称搜索每次从官方 API 获取最新列表，详情每次读取最新资料，不使用图片缓存的有效期缓存展会信息。仅当列表数据源故障时，可按 `stale_hours` 回退至最近 24 小时内的记录，并明确显示旧数据获取时间和降级信息；设置为 0 可关闭故障回退。地区精确名称表带有版本及来源，未知或重名归属不推测。没有出站回执的接入使用短码，实际引用与附件能力需分别验证。

`/` 表示 AstrBot 配置的唤醒前缀。详情标记原文节选和来源；缺失字段保留未明确，未核实状态显示未知。API 故障与不存在的 ID 分别反馈；缺少浏览器时给出部署操作，不切换排版体系。原始图片放在框架插件数据目录，插件不缩放或重编码。

主入口可在插件配置的 `command_entry` 修改；`function_aliases` 每行一项 `快捷入口=功能`，例如 `查展=查询`、`展会详情=详情`、`设置主题=主题默认`。别名直接绑定功能，主入口改名后仍然有效，与完整命令共享参数及机器人管理员权限。入口只填名称，不填 `/` 等唤醒前缀；保存后重载插件生效，旧入口会被清理。示例以默认 FEC 展示，实际提示使用配置后的入口；框架使用 `!` 前缀时输入 `!FEC 查询`。请在本插件配置中修改路由，避免同时在框架命令管理中重命名这些入口。

重复入口、未知功能或与其他已启用插件的命令冲突会明确拒绝加载，请修正配置后重载；后加载插件造成的冲突也会在使用时报告。`选择 <序号>`、`翻页 <页码>`、`下一页` 和 `上一页` 可省略短码，只使用本人在本聊天最近一次成功生成的查询；无记录或已过期时提示重新查询。明确短码和正确引用优先，无法关联引用时不会猜测最近列表。`下一页`/`上一页` 使用当前用户在当前聊天中该短码最近生成的页，未浏览过从第一页起算；记录跨重载保留。正确引用列表图时仍以被引用图片的页码为准。

每张图片附带独立输出码，`原图`（或 `原文件`）命令提交生成时的同一文件附件；输出码限所属聊天，默认 24 小时有效，重载不延长有效期。文件丢失或内容变化时提示重新查询。图片发送失败时，在有文件能力的接入尝试同一原文件附件；附件不可用或失败会明确提示。当前已实测本地 AstrBot WebChat 的图片与文件字节一致；Telegram、OneBot 的框架文件通道已接入，实际平台接收仍待验证，其余接入暂不声明附件能力。平台预览、压缩和长图接收限制由平台决定。

AI 总结默认关闭。机器人管理者可在插件配置启用并选择 AstrBot 已配置模型，保存后重载；插件没有独立模型 Key。摘要使用模型从介绍前 12000 字选择有序原文片段，最多 1000 字，不接受模型补写的内容；调用超时、失败、未选模型或输出不可用均回退原文节选。总结与节选都保留来源入口。

主题导入只允许机器人管理员：上传 ZIP 后回复 `/FEC 主题导入`；接入未提供引用文件内容时会提示。更新时回复 `/FEC 主题更新 local:标识`，包内标识须与目标一致。默认使用 `builtin:material`，用户可为查询、搜索、详情、选择、翻页或单图追加 `--theme <已安装标识>`，只影响本次输出。安装不改变默认值，普通导入不会覆盖已有标识；导入主题存放在插件数据目录，重载和插件更新保留。主题使用 HTML + Jinja2 与包内静态资源，契约和可运行样包见 [主题作者文档](themes/README.md)。执行 `python scripts/build_theme.py themes/material dist/material-theme.zip` 可打包样例。

内置 `builtin:material`（初始默认）与 `builtin:liquidglass`。主题优先级为单次指定、本会话默认、全局默认、初始 Material；会话按平台实例和群/频道/私聊身份隔离。只有机器人管理员能设置/清除默认值、改色、保存副本或导出主题，群主/频道管理员身份不自动取得权限。默认值不可用时明确报错，可单次指定可用主题或清除对应默认值，不静默换主题。

主色和 `light`/`dark` 模式独立保存，高级颜色只能修改主题声明的项，`主题配色` 可查看。配色按主题保存，对使用该主题的会话生效；与包版本独立，插件更新不覆盖用户状态。`主题副本` 克隆布局和当前配色为 `local:` 主题，后续源主题配色变化不影响副本。内置主题可选择预设图文排版；自定义布局、字号和间距通过导出 ZIP 编辑并以新标识导入。导出 ZIP 包含声明、布局与资源，独立配色仍保存在宿主数据目录；导入/另存副本不切换默认主题。

生成图片及查询记录在交互有效期结束后额外保留 24 小时，再于后续命令中分批回收；这段保留期不会延长原图或短码的可用时间。只回收已登记且位于插件图片目录内的过期输出，有效的共享引用和正在发送的文件受到保护。存在积压时随命令继续处理，平时最多每小时检查一次；删除失败记录会保留并重试，不阻断查询，也不清理用户主题或无关文件。

## 展会海报与排版

0.2.6 为 Liquid Glass 详情页增加对应展会宣传图的整页高模糊混色背景。介绍与来源面板透出大色区，保留折射、高光和清晰文字；标题与页脚区域做明暗保护。背景复用已加载的官方海报，不增加独立下载或图片来源；缺图时使用原有主题背景。卡片内的清晰海报仍按原比例显示。

0.2.12 将 Liquid Glass 的大范围混色、折射感和静态流光集中到详情页整页宣传图背景，大信息卡保持轻薄半透明表面与 1px 细边。状态和查询短码胶囊的淡染色直接跟随文字强调色，计划与短码偏蓝、延期偏琥珀；胶囊统一使用 20% 的同色染色，保留通透、折射与细边；卡片内不增加重复磨砂或白色面蒙层。详情标题旁独立胶囊使用同色的轻玻璃底。时间字段的日期待定说明为普通文字，不另加框，取消保留虚线。PNG 中的流光为定格光带，超长图关闭容易导致漏字的背景滤镜，保留淡染色、高光与色区层次。

新安装默认 `compact`（紧凑图文）；`poster` 使用更大的海报区域，`grid` 为双列目录。三种布局均为同一卡片内左文右图，海报高度贴合卡片、宽度按原比例自然延伸；图片内容不足的左侧由边缘取色补齐，以 10% 不透明度与模糊连续过渡。机器人管理者可在快速配置设置 `list_layout`，用户可用 `--layout compact|poster|grid` 为查询、搜索、翻页及全部结果单图选择排版。主题管理页可以选择预览排版，示例资料不代表真实展会。

翻页按显式参数、引用图片的排版、当前用户该查询最近使用的排版、查询初始排版依次选择；排版与页码跨重启恢复。查询快照保持原序号和展会的对应关系，新查询获取新资料。双列目录按从左到右、从上到下保持顺序。旧快照自动使用紧凑排版；旧主题继续使用主题自身布局，显式请求不支持的排版会提示。

列表与详情使用官方 API 返回的 `thumbnail` 和 `organization.logoUrl`。只访问 `images.furrycons.cn`，资源请求不携带数据 API 的 Authorization，不跟随重定向。图片在插件数据目录的 `image-cache/` 复用 7 天，读取不会延长原有效期；地址变化立即获取新资源，过期后重新获取，失败不使用过期图片。缓存总容量最多 256 MiB，按最近使用情况清理；单资源最多 24 MiB、4000 万像素，并检查实际图片内容。运行时通过 Pillow 处理方向、静态首帧及适合展示的尺寸，缓存不会包含在主题导出或安装包中。

列表和详情的海报均右对齐，按卡片高度等比缩放，宽度自然计算，不因卡片宽度再次放大；超出卡片的部分在外缘裁切。左侧没有图片内容时，从海报可见左边缘的上、中、下三段取色延展背景，并与模糊图层连续融合，文字保持清晰。详情左侧呈现时间、地点与主办方。图片缺失、超时或异常时显示占位并保留全部展会文字。Liquid Glass 的折射、高光、阴影和环境光作用于装饰层，正文保留清晰底色；支持浅深色及原有独立配色。超长图保留玻璃边缘、高光、阴影和色彩层次，并避开 Chromium 背景滤镜的漏绘问题。
